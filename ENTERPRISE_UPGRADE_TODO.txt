PURPOSE
-------

This file captures the broadest practical upgrade path from Angerona's current
single-host security suite into a defensible enterprise platform. It includes
product, architecture, security, privacy, fleet, reliability, deployment,
operations, compliance, usability, documentation, and long-range research work.

This is a TODO, not a claim that unfinished capabilities exist. A checkbox may
only be marked complete when its acceptance evidence is stored in the repository
or in a release evidence pack. Marketing language must never outrun proof.

--------------------

Status:
  [DONE]      Implemented and verified in the current repository.
  [PARTIAL]   Useful foundation exists, but the listed acceptance gate is open.
  [TODO]      Approved engineering work that has not been implemented.
  [DESIGN]    Architecture/threat model must be approved before implementation.
  [RESEARCH]  Experimental work; never imply production readiness.

  P0  Release blocker, trust boundary, data safety, or serious reliability risk.
  P1  Required for a credible enterprise fleet preview.

NON-NEGOTIABLE PRODUCT RULES
----------------------------

[DONE/P0] DEF-001  Keep Angerona defensive and non-destructive.
  - Simulations use inert, reversible markers and short-lived tagged processes.
  - Never ship real credential theft, exploitation, covert persistence, wipers,
    ransomware, destructive payloads, or denial-of-service behavior.

[DONE/P0] DEF-002  Keep local-first and offline-capable behavior as the default.
  - Optional egress is off until an operator enables a named integration.
  - Cloud use must show exactly what data leaves the host.

[PARTIAL/P0] DEF-003  Fail closed at every privilege and trust boundary.
  - Untrusted extension, policy, update, identity, or remediation proof -> deny.
  - Sensor read failure -> visible "unknown/degraded", never a false "healthy".

[PARTIAL/P0] DEF-004  Require human approval for destructive or high-impact response.
  - AI may explain and recommend.
  - AI must not silently kill, isolate, delete, change firewall policy, alter
    startup state, or modify enterprise configuration.
  - Emergency pre-authorized playbooks require scope, expiry, rollback, and audit.

[PARTIAL/P0] DEF-005  Separate detection evidence from conclusions.
  - Preserve raw observation, normalized event, analytic result, confidence,
    policy decision, operator decision, response action, and verification receipt.

[PARTIAL/P0] DEF-006  Make privacy a product boundary, not a settings footnote.
  - Minimize by default, redact before export, bound retention, support deletion,
    and document every optional outbound path.

[TODO/P0] DEF-007  Never claim "enterprise ready", "tamper proof", "zero trust",
  "AI-secured", or compliance/certification without objective release evidence.

[DECLINED/P0] DEF-008  Do not use stealth process names, process ghosting, covert
  collectors, hidden persistence, deceptive installers, or anti-analysis tricks.

[DECLINED/P0] DEF-009  Do not add a kernel driver for marketing value. A driver is
  only justified by a measured user-mode visibility or enforcement gap that
  cannot be safely solved with supported OS facilities.

TARGET PRODUCT SHAPE
--------------------

Preserve the standalone product. Add enterprise capabilities as optional layers:

  angerona-agent
    Windows endpoint service and local UI; remains useful while disconnected.

  angerona-sensor-system
    Low-footprint process/file/memory/event-log/AMSI/ETW sensor cluster.

  angerona-sensor-network
    Network/WFP/DNS/WLAN/connection sensor cluster.

  angerona-control
    Fleet enrollment, identity, policy, jobs, RBAC, audit, and admin API.

  angerona-ingest
    Authenticated event intake, validation, deduplication, buffering, routing.

  angerona-search
    Tenant-scoped indexed event store, hunts, timelines, retention, legal hold.

  angerona-case
    Incidents, evidence, tasks, response approvals, reports, exports.

  angerona-update
    Signed content and software distribution, canaries, rollback, health gates.

  angerona-console
    Multi-host web/desktop operator experience with SSO and scoped permissions.

  angerona-ca
    Device/workload identity issuance, rotation, revocation, and trust bundles.

  angerona-connectors
    Optional, sandboxed SIEM/SOAR/ITSM/identity/threat-intelligence adapters.

Architecture rules:
  - The local agent continues detecting and responding during control-plane loss.
  - Control-plane compromise must not grant arbitrary endpoint code execution.
  - Data and control planes use separate credentials, scopes, and rate limits.
  - Every remote command is typed, signed, authorized, expiring, replay-resistant,
    auditable, bounded, and mapped to a supported agent capability.
  - No generic remote shell in the enterprise control plane.
