confined diagnostic review. The underlying records bind their respective source,
origin and native retirement. Scopes overlap and must not be summed. These
results do not establish final whole-suite acceptance, current public-main CI
or live protection of the operator's actual Core generation.

## Final reliability changes

The optional monitor's worker waits for a single-use admission event. No native
work is admitted until Thread.start returns successfully. An uncertain start
creates a sticky hold for that optional monitor while the Core's other workers
continue. That failure never grants a retrying native owner or extra authority.

The scanner's GUI quit is queued only after authenticated STOP and successful
cleanup. Cleanup failure remains explicit rather than reporting successful
shutdown. Maintenance process ownership recognizes at most 16 harmless Python
prefix switches before its known entry point. A -c command or unknown entry is
not confused with an owned Angerona process.

## AI provider self-test and host assessment

The self-test explanation now distinguishes provider availability from verified
write custody of its per-machine installation. Required custody that cannot be
verified still produces FAIL. Clearer text does not turn that failure into PASS.

A separate read-only host assessment confirmed that the required write
protection remained unverified. No provider ACL was changed by that assessment,
and it establishes no malware, spyware or compromise verdict. Review the
provider's trusted installation/custody before rerunning its specific test.

## Final syntax, interoperability and host selfcheck

Final syntax validation compiled 1,673 Python files with zero errors and no application execution or bytecode writes. The unchanged cross-language protocol test passed using the verified offline Go compiler and the actual Python heartbeat and peer-alert readers.

The full offscreen harness completed 28 phases and retained one failed phase. All 86 modules were accounted for: 70 module checks passed, the optional AI provider check failed its required installation write-custody admission, and 15 were skipped with explicit prerequisites. The separate controlled pipeline check passed. Thirteen widget owners, thirteen readers and eight Python workers retired. This is **not an all-green host result**: the provider hold remains actionable and is not a malware verdict. Its original failed diagnostic reports were preserved.

The new signing screenshot renders the actual widgets with explicitly synthetic values and registered system fonts. It contains no host data and starts no inspection or export workers.

Guarded exact-commit publication, public image identity, current-head hosted checks and any actual Core-generation observation retain their own receipts. This document does not replace those proofs or claim live protection.

A real validly signed and enrolled positive deployment remains unaccepted.
The optional observer shares the Core job and has no independent recovery.
Same-user source tampering, administrator/kernel compromise, whole-root replay
and Source Observe network enforcement remain documented limits.
