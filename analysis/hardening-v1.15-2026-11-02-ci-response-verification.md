# CI diagnostics and native response verification

2 November 2026. Angerona 1.15.0 source-development follow-up.

The earlier published `380dc7b` finished with ten successful hosted checks and
five cancellations. Four Windows Python jobs reached their one-hour limit;
the macOS ARM installer job could not acquire a hosted runner. The Windows logs
contained five failure markers and stopped at 39%, without identifying the tests
or printing the exit journals. This was not a passing full-suite result.

## Reproduced test and diagnostic defects

A bounded collection-only run found 13,019 nodes. Excluding the twelve new
Auto Adapt cases provided a conditional ordering map for the earlier revision.
Targeted execution then reproduced four failures: hidden scanner widgets had
not delivered their queued presentation updates, one custody double omitted the
new event argument, and a terminal-proof fixture supplied stale evidence without
the current enrolled producer graph. The corrected fixtures exercise visible
Qt delivery, exact event forwarding, fresh authenticated evidence and actual
file/journal custody. Added stale, tampered and revoked-evidence cases require
no file effect.

The next mapped test used an old `exec()`-only Setup double. The production
window now requires a modeless dialog and its `finished` signal. A bounded
diagnostic captured the missing `setModal` error without entering its warning
loop; the original test remained failed. The revised test uses a real QDialog,
requires no preference change before explicit acceptance, and checks the owned
update path. The native after-action fixture likewise uses the returned Settings
dialog and requires one accepted result. Its native deadlines, response rules,
signed reports and independent target witnesses were preserved.

Windows CI now streams verbose test IDs with unbuffered Python output. An
explicit, step-scoped option mirrors wrapper stages while pytest runs. Each
emitter admits seven attempts of at most 1,024 ASCII bytes; failed attempts
consume capacity. Normal execution emits five markers. New records exclude
argument values, paths, environment contents and exception messages. Existing
independent journals, exit codes, cancellation, in-process pytest execution and
atexit brackets remain intact. An end marker does not prove subsequent native
interpreter finalization. The whole-job timeout remains one hour.

## Ownership and response efficiency

The first native after-action reproduction completed only 30 of 37 simulation
targets. Its manually constructed manager lacked the companion supplier normally
bound during application startup. Query-only inventory observations now expose
the actual retained Windows Job members, with exact native process identities,
short immutable leases and all-or-nothing publication. Truncated membership,
PID reuse, stopped ownership or uncertain handle closure rejects the observation.
These observations grant no detection, trust or response authority.

The fixture composes real Core and inventory observations on a retained
background worker. Its supplier is memory-only and raises unavailable on a failed
sample; it cannot silently drop the inventory companion. Other heartbeat roles
are explicitly absent because this fixture does not launch them. This change
does not claim a newly deployed service or alter production App enrollment.

That correction enabled process containment, but six file requests still expired
at the unchanged 30-second evidence limit. Bounded, test-only diagnostics matched
their retained original identities to authenticated events. They call the
original guard once and preserve its return or exception. The existing private
64-row/64-KiB stream reserves capacity for eight hold records; omitted or partial
captures remain visible. Recorded post-hold ages are not the guard's own samples.

Two avoidable operations were removed. Ordinary canary validation now relies on
the mandatory issuer verifier's full-scope check once per recheck. Exclusive
handoff retains its explicit full-scope check and actual file-pin, identity and
HMAC barriers. No validation result is cached across action boundaries. Process
response rejects invalid PIDs and explicit contracts with no process action
before constructing unused authority proofs. A missing contract argument keeps
its legacy default; an explicit empty contract cannot become that default.
Original evidence freshness, permissions and final mutation checks were preserved.
