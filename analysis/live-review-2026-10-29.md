## Demonstrated defects and scoped corrections

1. **Report classifications:** the toolkit adapter validated but discarded its
   source finding/reference/withdrawn subcounts and classification context. A
   report containing one historical contact and two contextual references
   therefore exposed three generic rows without an explicit partition. Preserve
   bounded source counts and row classifications, propagate them through direct
   and priority results, and label the existing after-action review. Preserve
   original report bytes, coverage, external `confirmed=False` and response
   holds. Clear current-run count fields at admission to prevent stale results.
2. **Retired process inventory:** multiple consumers reported the shared provider
   as retired. Cleanup overwrote the visible failure reason, and the owner's
   cached startup readiness could still say running after provider failure.
   Preserve the first failure, reconcile cached readiness and expose a bounded
   memory-only status projection. The historical failure cause is unknown;
   neither a deadline nor competing load has been established as its cause.
   Do not change provider deadlines, native custody, GUI-thread refusal,
   single-lifetime ownership or the absence of fallback/replacement collectors.
3. **Antivirus provenance:** the native adapter had already parsed source event
   time and XML, but the emitted view dropped source time and correlation IDs.
   Action records also dropped available native result fields when a differently
   named status field was absent. Preserve bounded source metadata separately
   from delivery time and describe reported actions without inferring success
   from an action name. Original alerts, severity, continuity and response
   boundaries remain intact; missing or malformed metadata stays explicit.
