# Angerona v1.14.1

28 October 2026 · source development maintenance

This update improves startup recovery, drive-space admission, dashboard layout
and operator STOP. The application and package metadata use 1.14.1; Windows
packaging derives 1.14.1.0. Component implementation versions remain independent.
The broader v1.15 integration milestone remains incomplete.

- Recovery copies have an aggregate budget and free-space reserve, with visible
  Block/Delete/Change choices. Windows source Safe Startup treats retained
  diagnostics and recommended free-space reserves as advisory, using leased
  working folders with bounded startup output and recognized-output reuse.
  Optional repair/download storage and security evidence retain their separate
  limits and authority.
- Source update staging permits two retained candidates, a 2 GiB aggregate
  budget and a 2 GiB volume reserve. Conflicts and earlier candidates remain
  available for review; insufficient capacity holds another preparation.
- Safe Startup records failed phases and tries bounded verified alternatives.
  An independent Windows startup dashboard paints before Python checks; recovery
  remains available when the main interface cannot open. Disposable probes have
  separate phase budgets and retain their entire owned native process tree.
  Original source is preserved before corrective replacement; recovered code
  still needs fresh checks and the dashboard-ready handshake. Each Retry
  reacquires working space inside its owned attempt loop; unavailable optional
  logging does not replace the returned application result.
- Dashboard boxes minimize individually. Startup opens all sections except
  Module health and activity; responsive tables expose additional fields through
  Filters, Columns and full-row details.
- Component EKGs beside resource status beat only for fresh real heartbeats.
  Missing, stale, stopped or unavailable evidence flatlines red; clicking shows
  component generations, heartbeat ages and the reason.
- Correct an environment adapter that prevented sidecar launches. The
  [mutual-recovery helper](../resilience-recovery.md) checks supervision or
  requests bounded recovery without creating a competing manager or clearing STOP.
- STOP and tray Quit record authenticated operator intent before teardown.
  Automatic recovery honors it. Configured model residency and owned processes
  are released; shared Ollama daemons and model files remain.
- Practice verification can observe an already completed response's delayed
  signed receipt without submitting the action again. Missing or invalid proof
  still fails verification.
- The [online manual](../master-manual.md), [PDF manual](../../Angerona_Master_Manual.pdf)
  and [45-second demonstration](../../assets/demo/angerona-demo.gif) explain the
  interface and security boundaries using synthetic public examples.

## Receiving the update

Source users can review canonical [main](https://github.com/Ag3nt47/AngeronaSuite)
and use the existing customization-preserving update workflow. Manual Check now
and optional daily discovery compare the actual source revision; daily discovery
remains opt-in. A source notification does not silently activate downloaded code
or overwrite local customizations. See the [update guide](../github-updates.md).

For source checkouts, Yes prepares an isolated candidate for comparison. Source
activation remains held; the running checkout is not automatically replaced.
Clean disjoint edits can merge into the candidate, while conflicts retain all
sides. Ignored local files stay in the original checkout. This is preparation
and review, rather than a silent source-code installation.

Installed users require an accepted newer signed release and its authenticated
upgrade assets. There is currently no stable GitHub Release for 1.14.1, and the
external signing authority remains unprovisioned. This source publication does
not auto-update existing installed binaries or bypass their trust gates. An
accepted package must be built, signed and independently verified before it can
be offered through that channel.

## Validation and limits

The [startup/storage review](../../analysis/startup-storage-recovery-2026-10-28.md)
records focused checks, actual startup and STOP observations, media verification
and explicit coverage gaps. Historical results retain their original versions;
GitHub checks must match the final published commit. Ring 3 collection,
same-user source trust and unavailable collectors retain their documented limits.
