# Angerona v1.14.0

This v1.14 development update adds live diagnostic review and tighter cooperation between
existing security components. The [issue register](../../analysis/live-debug-2026-10-22/README.md)
and [interaction map](../../analysis/live-debug-2026-10-22/interaction-map.md)
record the evidence, dependencies, fixes and remaining uncertainty.

All nine requested security integrations belong to this version. Their
[implementation and acceptance register](v1.14-security-integration.md) separates
tested behavior from work in progress and independently provisioned enforcement.
The evidence register distinguishes source validation from independently
provisioned enforcement; a version label alone proves neither deployment nor efficacy.

- **Live AI Review:** opt-in local Windows alert/error stream, a read-only Black
  Box review tab, bounded JSONL capture and record-bound advisory notes. The
  [guide](../live-debug-harness.md) documents how other AIs connect and repeat
  the reproduce, patch, test, publish and restart loop.
- **SpywareGuard window:** wider top-right black-spy button, responsive header
  sizing, a reusable dedicated window and existing integrity-lock enforcement.
  The intelligence banner has summaries, cached detail views, source-specific
  availability and dated offline references. Live downloads remain opt-in.
- **Module controls:** background **Turn all on**, progress, first-cycle pacing
  and explicit held/skipped results through existing lifecycle/policy gates.
- **Function moons:** separate colour-coded Core, Watchdog, Scanner and Black
  Box controls around the floating globe, with cached status and honest unknown
  freshness. Screen-edge geometry keeps their names visible.
- **Shared scanning:** immutable connection receipts let Scan Center reuse
  existing detector collection. An inert concurrent replay reduced nine OS
  enumerations to one; failures and stale/partial data stay visible.
- **GitHub checks and preserving custom code:** optional daily checks default OFF
  in Settings > General and Full Setup > Updates and storage. Manual Check now
  runs in the background. Downloaded source is staged separately with base/local/
  upstream bytes and explicit conflicts, preserving local customizations. Daily,
  setup and manual controls passed 179 with one optional native-8.3 skip. Activation
  always remains HELD; source HTTPS/a Git SHA/a clean merge is not release trust.
  See the [update guide](../github-updates.md).
- **Installer recovery preservation:** retain recoverable payloads through reviewed
  replacement/rollback exceptions. The27 confined controls passed;21 actual
  PS5.1 child receipts retired with no handle gaps. Durable crash reconciliation,
  restart health and trusted deployment remain separate, unproved gates.
- **Literal intelligence tooltips:** six external tooltip sinks escape entity-
  decoded summaries as literal text. Original Qt baseline 1 PASS/6 FAIL became
  sevenPASS after correction. This verifies formatting, not network/file/script
  execution or security authority.
- **Correctness and security:** stable runtime fingerprints; fresh executable
  approval hashes with file custody; narrower persistence execution parsing;
  exact health dispositions; helper identity checks; safer Qt/pipe teardown;
  bounded log parsing and per-client disk-persistence waits. Late independent
  retests cover witness cache and nonce freshness, sparse-recovery rejection,
  exporter startup cancellation, finite-snapshot completion, clock discontinuity,
  denied process collection and broker lease/dispatch freshness.
- **Verified readiness:** declarations, fresh collection, scoped detection tests
  and verified responses have separate stages, expiry and lifecycle invalidation.
- **Independent witness:** opt-in private mTLS/Ed25519 UGCAP checkpoints with
  retained heads, explicit enrollment, rollback conflicts and missing-evidence holds.
- **Authenticated approvals:** exact-operation signatures, canonical operator
  identity, alias deduplication, durable revocations and verified outcome gates.
- **Isolated response service:** native peer identity, installed-package and
  restricted-service checks around a diagnostic-only IPC surface. Production
  deployment and privileged mutation consumers remain held.
- **Windows Prevention and Independent Recovery:** background native inspection,
  exact staged plans and authenticated recovery contracts; explicit encrypted
  archive selection, byte-verified isolated drills and opt-in recurring tests.
  Local configuration and restore success do not establish runtime enforcement
  or independent backup custody. The tested revision is the archive signer's
  association; the local proof covers selected-inventory extraction and reread.
- **Identity inputs and replay quality:** opt-in local session/extension metadata
  collectors and declared-training/fixture separation checks for replay evaluation.
- **Dependency fixes:** current certifi and pip trust bundles with reviewed hash
  locks; the audited local environment reports no known vulnerabilities.

Source package metadata and all 86 built-in implementation labels declare
**1.14.0**; this does not assert a newly accepted installation artifact.
The module contract schema remains v12. Historical reports keep their original
version labels and validation dates. The existing master manual is unchanged. The [Markdown update guide](../github-updates.md)
contains current operator/AI instructions. An optional DOCX appendix remains
unapplied and undelivered after a renderer handshake failed before source open;
its historical54-page master-manual QA does not validate that appendix.

Source publication does not establish a signed Windows Protect installation.
Publisher signing, clean-VM package acceptance and the repository's protected
release workflow remain separate gates. No signing identity or installer trust
check is weakened to produce an artifact.

Protected historical alerts are retained. A reproduced false-positive mechanism
does not clear an inaccessible incident. The exact startup Qt delay and one
transient repair-fixture filesystem error remain open cause investigations.
