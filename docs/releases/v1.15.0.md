## Current implementation scope

- **Telemetry canaries:** retain generic process observations while separating
  actual kernel-ETW, native Sysmon and polling paths. Provider lifecycle,
  provenance, missing receipts and probe retirement remain explicit.
- **WER precursors:** correlate bounded creation/access records with current
  owned-process context. A dump request or suspend-capable access is a lead;
  stronger correlation requires its source identities and generation evidence.
- **Containment identity:** retain process and executable custody across a
  program-firewall transaction, its durable outcomes and exact managed rollback.
  The acquired file identity is transaction evidence, not proof of the original
  mapped executable or of socket admission.
- **Freshness composition:** bind a configured independent authority before
  Audit Log Integrity Guard and Network Trust admit persisted state. Preserve
  Smart Deception's pre-start binding and exclude lookalike external classes.
- **Windows rollback audit:** inspect bounded direct servicing-queue operations
  targeting fixed critical images, including the registry-selected local queue.
  Report lower disk versions and custom queue references for review. Keep older
  Windows.old recovery copies separate from scheduled replacements, and retain
  missing resources, unsupported actions and version-sampling gaps. This audit
  changes no OS file, update policy, boot state or reboot decision.
- **Independent recorder epochs:** dedicated authority-side append admission,
  separate Ed25519 archive signing, bounded local receipt/index storage, exact
  pending-commit reconciliation, historical change/loss checks and optional
  runtime enrollment. Network or storage holds preserve local protection.
  [Configuration, storage limits and freshness boundaries](../recorder-integrity.md).
- **Isolated engine boundary:** validate the installed virtual service account,
  token, package and private data-root custody before loading configuration,
  keys or sensors. A separate desktop console exposes status only. Actual
  signed installer/SCM provisioning and clean-VM acceptance remain required.
- **TPM verification:** issuer-pinned physical-device enrollment, signed fresh
  counter/extend/counter observations and typed checkpoint binding, with a
  read-only Windows TBS adapter and pure policy-write plans. This does not
  provision hardware, execute NV writes or provide atomic digest CAS. An
  accepted external platform enrollment and protected writer are required.
- **Managed driver-policy service:** an explicit installed v2 profile composes
  the native backend with fixed reviewed materials, server-owned plans,
  independently OS-bound approvals, durable single-use capabilities and an
  asynchronous bounded request surface. Default v1 remains diagnostic-only.
  The current profile manages an owned unsigned multiple-policy deny policy;
  real signed deployment and native enforcement acceptance remain separate.
  [Workflow and deployment scope](../managed-driver-policy.md).

Additional lifecycle changes retain native pipe, process, token and SCM owners
when completion or cleanup is uncertain, drain recorder/enrollment tasks before
SQLite closes, and close partially constructed recorder connections. Historical
recorder reads use freshly verified indexed row identity rather than repeated
whole-ledger scans. The legacy retrieval helper no longer creates or reads a
knowledge-base file at import, preserves existing custom files and bounds its
advisory output. Watchdog wording now distinguishes worker lifecycle/deadline
observations from detector health.
Counter-Agentic now includes bounded socket state, endpoint and role details;
only explicit LISTEN plus a matching local port is labeled a listener. An
inference-port observation does not assert hijacking, initiation or locality.
Detection criteria, HIGH severity, exact-path/digest approvals and deduplication
are unchanged.

Crash logging now exposes per-target opening/STARTUP results, Python/thread/Qt
hook arming and its single selected native-fault output. Partial/unavailable
arming is recorded without blocking dashboard startup. This is an observability
patch, not a repair for the unresolved native shutdown crash described below.

## Major hardening acceptance

| Requested area | Required distinction |
| --- | --- |
| Vulnerable drivers / telemetry blinding | A missed scoped echo is coverage with unconfirmed cause. Driver-policy activation needs a verified native backend and independently reviewed audit/enforce/recovery acceptance. |
| WER / process suspension | Post-event correlation does not guarantee pre-dump interception. Antimalware PPL requires certified ELAM and signed native deployment; it does not grant WinTCB authority. |
| Executable replacement / egress | Retained transaction custody improves the user-mode action window. PID-bound ALE admission and established-flow teardown need a separately accepted native enforcement backend. |
| OS / whole-root rollback | Vendor OS mitigations, authenticated independent freshness and policy-bound hardware are separate controls. An unauthenticated NV counter does not implement digest/head CAS. |
| Same-user ledger forgery | Service-private custody and independent sealed epochs require their actual enrollment and verification paths. A same-user hash chain cannot promise Python secure erasure or whole-root rollback resistance. |

Existing preferences, user additions and authenticated originals must survive
this upgrade. Source Observe retains its existing authority limits. Unavailable
collection, uncertain identity and failed compensation remain visible; they are
not converted into successful protection receipts.
