# Angerona v1.14.2

29 October 2026 · source development update

This update connects curated spyware checks, priority scan controls and verified
breach review in the desktop interface. The source/application version is
1.14.2; Windows packaging derives 1.14.2.0. Component implementation versions
remain independent. The broader v1.15 integration milestone remains incomplete.

## What changed

- **GitHub Tools** opens curated scanners, existing source review and analysis,
  settings, verification, managed revert and visible credits. The native
  **SpywareGuard > Zero Breach** tab shares the same controller and job state.
- The complete **Zero Breach Toolkit v0.1.10** engine is bundled at exact commit
  `81bd556ba604685dbd1c0ecb48138c10f43cccf8`, with Apache-2.0, research-data and
  optional-rule notices retained. Standard-library preparation adds no pip
  dependencies to Angerona's environment. Optional restore selects that pinned
  release rather than an arbitrary repository or newest branch.
- Integrated modes cover default, full, browser and selected-target checks;
  explicit local phone inputs, quick/preview, local indicators and existing
  Windows records have their own coverage limits. Advanced terminal menus,
  dependency installation, feed updates and acquisition remain held until
  separately managed adapters are accepted. The complete official pinned
  release remains linked for review and standalone setup.
- **Spyware Scan** schedules selected native and curated checks with scanner
  toggles, Above normal/High priority, resource limits and copied CPU/RAM/I/O
  and privilege-coverage state. The default requested routine-background pace
  is 10%; critical control, heartbeat and event intake keep their cadence.
  This is scheduling intent, not a guaranteed CPU split or REALTIME scheduling.
- The scan screen separates scope, included checks, progress, explanations and
  resource details. Its red **SpywareScan** button defaults to supported
  **Entire PC** checks, with click-to-change scope and wheel-safe options.
  Per-check and overall progress show current task/item, elapsed time and an
  estimate when measurements support it. Unknown totals remain explicit.
  Timeout reasons and partial progress remain visible; configured longer
  budgets reach the actual operation and cancellation retains its native owner
  until terminal. Expandable explanations and reduced-motion support keep the
  current work readable. Auxiliary windows fit the available display area.
- Open a single shared after-action report automatically after a requested scan
  finishes and its selected scanner workers stop. Cancelled, failed and partial
  runs retain their reasons and coverage gaps in the same review.
- Offer a separate per-run allowance up to four hours for large full scans.
  Saved defaults and the saved-setting maximum are unchanged, as are storage,
  memory and CPU-rate limits. The allowance is a finite deadline, not an ETA or
  a guarantee that every host completes. Completed scanner summaries show 100%
  while aggregate progress still waits for the remaining selected work.
- Handle generated temporary files disappearing during active quota accounting,
  including the scanner's atomic report-write names. Keep stable controls,
  installed artifacts and retained reports strict; unknown entries, redirects,
  permission failures and exceeded storage limits remain explicit holds.
- Distinguish source toolkit findings, contextual references and withdrawn
  indicators in scan summaries. Preserve bounded classification context and
  explicit coverage gaps without granting external reports response authority.
- Keep shared process-inventory readiness consistent with the provider's cached
  state and retain its first failure through cleanup. Bounded status diagnostics
  expose this availability gap; they do not automatically replace the collector
  or attest complete process coverage.
- Preserve Defender native source time, exact identifiers and available action
  result fields in retained events and the diagnostic stream. Keep delivery
  time distinct and avoid inferring successful remediation from an action name.
- Retain native Base64 mesh-signature metadata and generic SOAR input links in
  diagnostic export and offline summaries. Signature encoding and observed bus
  mode remain advisory; the existing verification flag alone does not establish
  enrolled producer identity or response authority.
- Recognize strict bare loopback host-and-port values from existing local AI
  settings at runtime and in matching previews. Preserve the stored value,
  cloud URL validation, explicit Send consent and listener-attestation holds.
- Repair the isolated toolkit's temporary-report writer without relaxing
  descriptor ownership or output limits. Actual pinned-engine tests exercise
  positive/negative reports, browser-query progress and deadline retirement.
- A **Breached** warning, case-linked critical report and red/orange borders
  require qualified fresh native evidence. Third-party findings, health alerts,
  exposure, practice, remote Observe and critical severity alone cannot create
  that authority. Investigate and Trace support read-only follow-up; Isolate,
  Kill, Patch and Lift expose their exact target and authority requirements.
  The case's Compromised card/footer state preserves ordinary engine scores
  and counts.
- Supported network lockdown goes through Adversary Combat's existing worker,
  saved policy, original host-scope contract, authenticated journal and verified
  signed installed Protect/Administrator authority. Source Observe shows held
  response controls. Scope and effective-policy ambiguity cannot become a
  verified containment result.
- **Lift Lockdown** verifies removal of only the managed rules and preserves
  unrelated firewall policy and preferences. A saved same-case lift prevents
  automatic relocking of that case; new evidence can create a different case.
  Lift and review resolution are separate. STOP does not silently remove a
  persistent lockdown.

## Storage and execution

The third-party engine runs only in a separate owned ordinary-user source
process, never in Angerona's core or GUI interpreter. Installed/elevated
execution remains held pending an accepted ordinary-user broker. No selected
repository, imported report or AI instruction can become arbitrary executable
code through this integration.

Each job has private working paths, native process custody, bounded managed
output and validated reports. Default working-data and retained-report budgets
are 256 MiB and 64 MiB, with at most eight retained report sets. Python writers
and copies cooperate with limits; native writers are monitored, not constrained
by an operating-system filesystem quota. Optional scan admission requires
3 GiB free plus its working allowance. A tool hold does not block core startup.
Revert affects the managed engine; preferences, reports and modified or unknown
originals remain preserved. Incomplete cleanup or uncertain process retirement
stays explicit.

## Validation and limits

The follow-up corrects outer-frame sizing on scaled displays and explicit
current-user ownership when Windows creates private toolkit files and logs.
Strict ownership checks remain in place. Startup diagnostics show the current
hold reason before historical repair details; a full optional recovery cache
still permits normal dashboard launch and preserves its existing copies.

The [integration review](../../analysis/curated-tools-breach-2026-10-29.md) records
scoped offline tests, native fixtures, interface layouts and exact process
retirement. It distinguishes these checks from actual host scans, packet-drop
tests, enterprise policy deployment and field detection efficacy. No real host
network or process response was exercised for the public demonstrations.
Historical manual and README test totals retain their dated scope; final
GitHub checks must match the published commit.
