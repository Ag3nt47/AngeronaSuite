Current **1.16.1 source follow-up**:

The ordinary Windows desktop source app has separate source-session STOP
coordination. Dashboard STOP and tray Quit share modeless confirmation controls.
Each session starts unlocked; the optional Lock STOP prevents accidental use of
these local controls. Unlocking and confirming Stop are separate actions. This
lock does not protect against the same user, an administrator or the kernel, and
does not grant or replace installed-service authorization.

An accepted source STOP inhibits its captured family's automatic recovery.
Shutdown targets exact Angerona-owned process generations and retained workers;
unrelated Python applications and shared AI servers remain running. Releasing a
configured model's residency on a shared server also affects that model's
residency for other applications. Downloaded models, preferences, alerts and
authenticated evidence are preserved. Unknown cleanup remains incomplete;
closing a window or returning from a cleanup callback is not exit proof.

The pre-bridge targeted cohort passed **682 tests with 2 skips**. The canonical
launcher bridge correction, fresh checks after it, live-family STOP acceptance,
and exact-commit GitHub publication remain pending. Earlier private native-token
checks do not prove complete live-family shutdown or signed installed Protect.

Earlier **1.15.1 source follow-up**:

- File Integrity Monitor receipt issuance and historical Red Team verification now use the same current per-root coverage schema, root lists, digests and aggregate counters. This corrects a mismatch that discarded genuine complete scan evidence. Incomplete, budget-exhausted or inconsistent coverage remains ineligible; exact object, lease, generation and signature checks still apply. A test marker alone earns no detection credit.
- Mobile bridge health preserves a failed send/receive receipt at **40**, while displaying any separate authorization or lockout hold. An authorization-only or lockout hold remains **60**; a receipt-authority fault takes priority at **0**. These are module health scores, not protection percentages. The change does not authorize mobile commands or claim recipient delivery.
- **Settings > Watchdog** now has its own contextual Info and matching source-sandbox metadata. Unsigned monitoring remains off by default, shares Core's child-job lifetime and cannot recover Core independently. Signing and protected enrollment remain separate requirements; selecting a candidate inspects it as data. Opening isolated source copies grants no installation or response authority.
- **Coverage warnings stay visible without implying an attacker.** Only exact typed FIM or network incomplete-telemetry records qualify for this health classification. High severity and original evidence remain. Genuine file/network findings retain their threat handling, and filenames containing lifecycle phrases cannot hide real file changes. Unknown or malformed records remain conservative; classification grants no response authority.
- **A held STOP is described accurately.** The notice explains that authorization was not established, Angerona has not exited and the notice cannot verify protection. It no longer assumes a declined UAC prompt. Protected control admission and cleanup behavior are unchanged.

These are focused source and fixture corrections.
